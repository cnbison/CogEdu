## 2. 断点与布局形态

| 断点 | 导航形态 | 内容区 |
|---|---|---|
| **≥1024px（主战场）** | 左侧固定侧边栏（展开 220px） | 宽内容区，讲解页白板全幅 |
| 768–1023px（平板竖屏/小窗口） | 侧边栏收窄为图标栏（64px） | 单栏，讲解页仍横向最大化 |
| <768px（手机，降级） | 侧栏隐藏，抽屉导航（汉堡按钮唤出）+ 保留现有底部 Tab 二选一（见 §9 决策点 D3） | 现状窄版心即可 |

> 现状问题对照：学生端登录页 420px / 内容版心 720px / 底部 5 Tab——本设计稿以侧边栏 + 宽内容区整体替换，**不是**在旧壳上打补丁。

## 3. 导航模型：SidebarShell 工作台

```
┌──────────┬────────────────────────────────────────────────┐
│ CogEdu   │  顶条：页面标题 · 用户名 · 退出                 │
│ 学习     ├────────────────────────────────────────────────┤
│          │                                                │
│ ◈ 今天   │                                                │
│ ✏ 答题   │                                                │
│ ▶ 讲解   │              内容区（宽）                      │
│ ◎ 我在哪 │                                                │
│ ↗ 成长   │                                                │
│ ▤ 报告   │                                                │
│ ⛨ 授权   │                                                │
│ ⚙ 设置   │                                                │
│          │                                                │
│ [fold]   │                                                │
└──────────┴────────────────────────────────────────────────┘
```

**信息架构三原则**：

1. **一级导航 8 项全平铺**——解决现状"Report/GuardianLinks/Scene 在底栏之外只能从 Home 深入"的可达性问题。侧边栏容量天然支持：
   - 现有 8 个路由全部成为一级导航：今天 / 答题 / 讲解 / 我在哪 / 成长 / 报告 / 授权 / 设置
   - **"讲解"独立成一级项**（现状藏在 Home 卡片里）——它是 Phase 3 核心资产的主入口
2. **扩展槽位预留**（Phase 4-6 新功能有处安放，这是本次重设计的根本动机）：
   - Phase 4 → "诊断"（误概念专项视图，学生侧简化版）
   - Phase 5 → "资源"（教学素材/知识库入口）
   - Phase 6 → "探索"（GeoGebra 交互构造）/ "练习"（检索式练习）
   - 槽位用分组标题预留（导航下半区"学习工具"组），上线一项亮一项，**不提前渲染死链**
3. **导航状态即路由状态**——沿用 NavLink 激活态，路由表零改动（HashRouter 路径不变，收藏/复看链接不失效）

## 5. 讲解场景页（核心页面，桌面布局）

**设计原则：白板是主舞台，字幕/大纲/控件是辅栏；播放时白板占满可用宽度的全部。**

```
┌──────────┬──────────────────────────────────────────────────────────┐
│ 侧边栏   │  讲解 · 一元一次方程 · 第 2/5 页          [生成进度 3/5]  │
│          ├──────────────────────────────────────────────────────────┤
│          │                                                          │
│          │                                                          │
│          │                 白板主舞台（16:9 等比缩放）              │
│          │                 高度 = 视口高 − 顶条 − 控制条             │
│          │                 宽度随高度反推，水平居中                  │
│          │                                                          │
│          │                                                          │
│          ├──────────────────────────────────────────────────────────┤
│          │  ◀ 上一页   ▶ 播放/暂停   ⟳ 重播本页   下一页 ▶          │
│          ├──────────────────────────┬───────────────────────────────┤
│          │  字幕（当前讲解词，滚动） │  本页大纲要点 / 已生成页缩略   │
└──────────┴──────────────────────────┴───────────────────────────────┘
```

要点：

- **白板尺寸策略反转**：现状是"版心 720px 限制 → 画布缩到版心内"；新方案是"**先给白板最大可用高度**（视口高 − 顶条 − 控制条），按 16:9 反推宽度"，在 1366×768 笔记本上白板约 1150×646，比现状放大约 60%
- 字幕栏与大纲栏在 ≥1024px 双栏并排；768–1023px 时字幕保留、大纲折叠为抽屉
- **生成等待态**（渐进渲染）：白板区显示已生成场景的骨架占位 + "第 n 页生成中…"，字幕栏显示实时进度（复用现有轮询逻辑，只改布局容器）
- Phase 3 vanilla 模块照常挂载：whiteboard.js/renderer 接口、playback.js 状态机、formula.js KaTeX 全部不动，React 宿主只换外层容器与尺寸注入

## 6. 答题页（桌面布局）

```
┌──────────┬──────────────────────────────────────┬───────────────────┐
│ 侧边栏   │  题目区（主，约 60% 宽）             │ 答题侧栏（约 40%）│
│          │  ────────────────────────────        │  我的作答（输入） │
│          │  题干（大字号，行高 1.7）            │  ─────────────    │
│          │                                      │  策略提示         │
│          │                                      │  （warmup/adaptive│
│          │                                      │   标签可视化）    │
│          │                                      │  ─────────────    │
│          │                                      │  本场已答 n 题    │
└──────────┴──────────────────────────────────────┴───────────────────┘
```

- 题目区与作答区**同屏可见**（现状手机端题干与输入框上下滚动）——学生边看题边作答，消除滚动迷失
- 768–1023px：作答侧栏移到题目下方

## 10. 技术实现约束（施工时的硬边界）

1. **Phase 3 vanilla 模块零改动**：`web/student/whiteboard.js|playback.js|formula.js` 不动一行，`tests/js/` 26 例必须原样全绿
2. **契约测试延续**：`test_frontend_react_wiring.py` 19 例锁语义不放松；新增桌面布局 grep 锁（如：ScenePlayer 容器必须使用视口高度变量、禁写死 720px 版心）
3. **白板尺寸注入方式**：React 宿主通过 CSS 变量传可用高度给 wb-stage（等比缩放逻辑已在 whiteboard.js 内，勿重复实现）
4. **导航数据单一来源**：侧栏导航树定义为一个 TS 常量（含 Phase 4-6 槽位注释），App.tsx 与降级抽屉共用
5. **不动后端**：本轮纯前端布局重构，API/路由零改动
6. **构建/发布流程不变**：dist 不入库，发布前 `cd web/frontend && npm run build`
